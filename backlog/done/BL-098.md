# BL-098 - Administration : onglets, indicateurs par profil et stats
- **Catégorie** : web
- **Priorité** : 2
- **Description** : la page `/admin` en un seul écran trop chargé. La découper en onglets
  (liste des profils, stats avec usage de la semaine, retours) portés par `?onglet=`, et
  enrichir chaque ligne : nombre de journées/résumés produits sur 7 j et 30 j, coût par
  résumé, profil choisi (gabarit reconnu d'après le texte du profil, sinon « Personnalisé »),
  régime de sécurité et nombre de catégories. Un coût inconnu affiche 0 plutôt que « ? »,
  le modèle sans tarif restant signalé à côté. Valeurs du tableau sur une seule ligne,
  tableau défilant horizontalement. Onglet stats : camemberts de la répartition des profils
  et des types de sécurité, et nombre de personnes par catégorie suivies.
- **Bénéfice attendu** : l'administrateur voit en un écran qui produit, à quel coût, avec
  quel profil, et comment la base se répartit.
- **Tests d'acceptation** :
  - [x] les trois onglets répondent à `?onglet=profils|stats|retours`, paramètre inconnu ramené à la liste ;
  - [x] chaque ligne porte journées 7 j / 30 j, coût 7 j / 30 j, coût par résumé, profil choisi, sécurité, nombre de catégories ;
  - [x] un coût inconnu ou une tarification incomplète affiche 0, sans « ? » ;
  - [x] les stats rendent les deux camemberts et le décompte par catégorie ;
  - [x] `npm run check` et `npm test` verts.
- **Réalisé le** : 2026-11-27
- **Livraison** : branche admin-stats-onglets
- **Notes** : « ne pas compter les jours sans coût dans les quantités » appliqué là où c'est calculable : l'API ne rend pas de coût par journée, seulement des totaux 7 j / 30 j ; un coût inconnu vaut donc 0 et le coût par résumé 0 quand on ne sait pas. Camemberts en SVG sans dépendance (`web/src/routes/admin/Camembert.svelte`). La fausse API des tests gagne la route `GET …/profils/{u}/couts`.
