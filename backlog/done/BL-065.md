# BL-065 — La tournée ignore les axes déclarés dans le profil
- **Catégorie** : pipeline
- **Priorité** : 1
- **Description** : `AppConfig.pour(lecteur)` (`rssresume/config.py`) recopie du document de la
  personne le profil, la stack, le régime de sécurité, le prénom, les destinataires, les catégories
  (et, depuis BL-022, les flux exclus), mais pas `axes`. Dans la tournée multi-profils, `config.axes`
  reste donc celui de l'installation (`from_env()`, c'est-à-dire les axes par défaut en mode base
  ou dossier) : les axes d'un gabarit (BL-041) ou déclarés à la main n'atteignent jamais le
  scoring (`DigestService` lit `self._config.axes` pour l'empreinte, le filtre des thématiques et
  l'appel au modèle). Aucun test ne le couvre. Ajouter `axes=personne.axes` à `pour()`. Attention :
  l'empreinte de scoring dépend des axes, la première tournée après correction renotera les
  articles des profils qui en déclarent.
- **Bénéfice attendu** : le scoring de chaque personne suit enfin ses propres axes, ce que
  promettent les gabarits par métier.
- **Réalisé le** : 2026-11-23
- **Livraison** : branche `backlog/BL-065-axes-tournee`
- **Tests d'acceptation** :
  - [x] `pour(lecteur)` porte les axes du profil du lecteur ;
  - [x] dans une tournée de deux profils aux axes différents, chaque scoring reçoit les siens ;
  - [x] un profil sans axes garde les axes par défaut.
