# BL-094 - Marquer les journées lues sur le site
- **Catégorie** : web
- **Priorité** : 1
- **Description** : le site n'indique nulle part si une journée a déjà été lue ou écoutée.
  Rappelé en revue du 2026-11-26 : « il va falloir le faire vite ». Marquer une journée
  comme lue pour un profil (consultation des pages du résumé, ou écoute audio terminée),
  stocké dans la base du site, et l'afficher dans la liste des résumés : titre ou pastille
  distincts, journée courante exclue jusqu'à son marquage. À distinguer du marquage comme
  lu des articles dans FreshRSS, qui reste tel quel (voir BL-056).
- **Bénéfice attendu** : un inscrit retrouve d'un coup d'œil ce qu'il n'a pas encore lu.
- **Tests d'acceptation** :
  - [x] consulter les pages d'une journée la marque lue pour le profil connecté ;
  - [x] écouter l'audio d'une journée la marque lue aussi, sans double comptage avec la consultation ;
  - [x] la liste des résumés distingue visuellement lues et non lues, sans rien montrer hors session ;
  - [x] deux profils n'écrivent pas dans le marquage l'un de l'autre ;
  - [x] `npm run check` et `npm test` verts.
- **Réalisé le** : 2026-11-26
- **Livraison** : branche backlog/BL-094-journees-lues
- **Notes** : « journée courante exclue jusqu'à son marquage » lu comme : aucune règle de date,
  une journée (celle du jour comprise) n'est lue que si elle a été ouverte ou écoutée. Table
  dédiée `journees_lues` (migration 9) plutôt que `consultations`, qui note le jour de visite
  et non la journée lue. Les liens « Lire le résumé » de la liste sont en préchargement `off` :
  le survol, et même le toucher sur mobile, aurait marqué la journée sans l'ouvrir. Une API
  du résumé indisponible n'empêche pas le marquage d'une écoute. Page de confidentialité
  complétée. Les lecteurs de la page journée ne signalent pas l'écoute : la page marque déjà
  à l'ouverture.
