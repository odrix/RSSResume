# BL-066 — Le site n'efface plus les clés du profil qu'il n'édite pas
- **Catégorie** : web
- **Priorité** : 2
- **Description** : `PUT /api/v1/profils/{username}` remplace le document entier
  (`AnnuaireSqlite.modifier`), et le site n'envoie que les clés qu'il connaît (`corpsProfil` dans
  `web/src/lib/server/api-resume.ts`). BL-045 a fait conserver `axes` et `categories` par « Mon
  profil » ; `flux_exclus` (BL-022), et toute clé à venir, est encore effacé au premier
  enregistrement depuis le site, sans rien dire. Corriger durablement : soit le `PUT` fusionne les
  clés absentes du corps (et un `null` explicite supprime), soit le site renvoie le document complet
  qu'il a lu. Puis permettre d'éditer `flux_exclus` dans « Mon profil » (liste de titres de flux),
  ou le rattacher à BL-046.
- **Bénéfice attendu** : un réglage déclaré par l'API ou par un gabarit survit à une retouche du
  prénom.
- **Tests d'acceptation** :
  - [ ] enregistrer « Mon profil » conserve `flux_exclus` ;
  - [ ] une clé inconnue du site ne disparaît pas à l'enregistrement ;
  - [ ] `flux_exclus` se lit et se modifie depuis « Mon profil » ;
  - [ ] suites Python et web vertes.
