# BL-096 — Unifier le stockage : la base et les sorties
- **Catégorie** : pipeline, web
- **Priorité** : 4
- **Description** : « un peu la foire des données » (revue du 2026-11-26) : les résumés et
  audios vivent dans des fichiers sous `output/`, les comptes et sessions dans SQLite du site
  (`web/src/lib/server`), le cache de scoring dans FreshRSS tags en attendant BL-056, des
  indicateurs dans la base du site (BL-072). Faire l'inventaire de ce qui est où, décider pour
  chaque donnée un seul lieu de vérité (SQLite pour tout ce qui est consulté par le site ;
  fichiers : régénérables, exclus du site), documenter la décision dans FONCTIONNEMENT, et
  migrer au moins une famille de données à l'essai. Plan à faire valider avant migration :
  l'objectif est la lisibilité, pas une réécriture.
- **Bénéfice attendu** : on sait où vit chaque donnée, la suppression, le nettoyage et la
  sauvegarde se raisonnent.
- **Tests d'acceptation** :
  - [ ] un inventaire écrit (FONCTIONNEMENT) dit pour chaque donnée son lieu de vérité ;
  - [ ] la famille migrée est servie depuis le nouveau lieu, l'ancien est retiré sans code mort ;
  - [ ] la suite unittest et les tests web restent verts après migration.
