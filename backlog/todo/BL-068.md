# BL-068 - Confirmation d'inscription robuste
- **Catégorie** : web
- **Priorité** : 2
- **Description** : deux défauts de `Inscription.confirmer` (`web/src/lib/server/inscription.ts`),
  relevés pendant BL-045. **Double envoi** : deux POST simultanés sur `/confirmer/<jeton>` lisent
  tous deux un compte non confirmé ; le second reçoit le 409 de l'API (le profil vient d'être créé
  par le premier) et affiche « Ce nom d'utilisateur est déjà utilisé… Contactez l'administrateur »
  à une personne dont le compte est bel et bien confirmé, sans consommer son jeton. Sur un 409,
  relire le compte : s'il est confirmé, consommer le jeton et rendre le succès. **Catalogue
  réimporté** : la copie du gabarit gardée dans le brouillon peut nommer une catégorie qui n'existe
  plus ou n'est plus publique au moment de la confirmation ; l'API répond 422 et le lien échoue à
  chaque clic. Retomber sur un profil sans catégories (tout le catalogue) en le signalant, ou
  écarter les seules catégories disparues.
- **Bénéfice attendu** : aucun message d'erreur à une personne dont l'inscription a réussi, aucun
  lien de confirmation définitivement cassé.
- **Tests d'acceptation** :
  - [ ] un 409 sur un compte déjà confirmé rend le succès et consomme le jeton ;
  - [ ] une catégorie disparue du catalogue ne fait pas échouer la confirmation ;
  - [ ] l'email de bienvenue part toujours une seule fois ;
  - [ ] `npm run check` et `npm test` verts.
