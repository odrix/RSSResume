# BL-084 - Autre mode de connexion : passkeys
- **Catégorie** : web
- **Priorité** : 3
- **Dépend de** : BL-083 (compte sans mot de passe, page _Compte_, envoi d'emails)
- **Description** : pouvoir se connecter avec une passkey (WebAuthn) à la place du
  mot de passe. Choix possible dès la création du compte (email + passkey). Depuis
  _Compte_ : ajouter, renommer, supprimer des passkeys, et ajouter un mot de passe.
  - Plusieurs passkeys par compte ; passkeys synchronisées acceptées ; une passkey
    seule suffit. L'email reste obligatoire : le magic-link (BL-083) sert de
    récupération en cas de perte de toutes les passkeys.
  - Un compte garde toujours au moins une méthode de connexion : supprimer la
    dernière est refusé.
  - Logique WebAuthn dans l'API Python (`webauthn`), qui possède SQLite ; le backend
    Svelte relaie et crée la session (`@simplewebauthn/browser` dans le navigateur).
  - Challenge à usage unique, expirant (5 min), stocké côté API. RP ID et origin
    lus depuis `.env` (valeur `localhost` en dev). Stockage : clé publique, compteur
    de signature, transports, nom, dates. `user_handle` aléatoire, pas l'email.
  - Navigateur sans WebAuthn : option passkey masquée. Boîte de dialogue annulée :
    retour au formulaire sans erreur.
- **Bénéfice attendu** : faciliter la connexion et les premiers essais, tout en
  gardant un très bon niveau de sécurité.
- **Tests d'acceptation** :
  - [ ] créer un compte avec une passkey crée un compte sans mot de passe, connecté ;
  - [ ] un compte passkey-only se connecte avec sa passkey ;
  - [ ] ajouter un mot de passe dans _Compte_ : les deux méthodes fonctionnent ;
  - [ ] supprimer la dernière méthode de connexion est refusé ;
  - [ ] un challenge expiré ou rejoué fait échouer l'authentification ;
  - [ ] un compte qui a perdu ses passkeys se reconnecte par magic-link et en ajoute une ;
  - [ ] le login par mot de passe existant est inchangé ;
  - [ ] `.env.example` documente RP ID et origin.
