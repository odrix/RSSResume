# BL-080 — Compléter les écoutes et les retours dans l’administration
- **Catégorie** : web, avec la lettre côté `rssresume/api` et `newsletter.py`
- **Priorité** : 2
- **Dépend de** : BL-075
- **Description** : compléter les indicateurs ajoutés par BL-072 avec les écoutes audio réellement servies depuis l’email ou le site, et le nombre de retours « utile / pas utile » produit par BL-071. Tant que BL-075 ne livre pas les audios par lien, les écoutes depuis l’email restent hors mesure.
- **Bénéfice attendu** : voir en un écran qui écoute, qui revient avec un avis utile ou négatif, et qui décroche.
- **Plan validé** :
  - migration SQLite suivante : ajouter une table `ecoutes` `(compte_id, jour)` avec clé primaire composite, ou étendre un objet métier unique pour les usages par profil ; ajouter une table `retours` `(profil_id, journee, verdict)` avec contrainte `utile`/`pas_utile` et clé empêchant deux retours du même profil pour une même journée ;
  - ajouter dans `RelaisAudio` un compteur persistant après livraison HTTP réussie, sans compter les réponses 404/403/416 ou les tentatives incomplètes ;
  - compter une écoute une fois par profil, par jour d’écoute et par journée audio consultée ; BL-075 fournit les liens durables nécessaires aux écoutes depuis l’email ;
  - ajouter aux pages du résumé les liens de retour « utile / pas utile » portés par BL-071, sans afficher ni accepter les retours hors session conformément au choix retenu par BL-071 ;
  - étendre `Comptes` ou une classe métier dédiée pour lire les écoutes 7 jours, les retours 7 jours, le désabonnement et les consultables, puis fusionner ces données dans `LigneAdmin` ;
  - afficher les colonnes « Écoutes 7 j » et « Retours 7 j » dans `/admin`, remplacer l’encart provisoire par les valeurs réelles une fois la dépendance BL-075 levée, et garder les limites explicites si une écoute n’est pas traçable ;
  - aucun outil tiers, aucune nouvelle dépendance, aucune variable d’environnement nouvelle ;
  - fichiers principaux attendus : `web/src/lib/server/base.ts`, `web/src/lib/server/comptes.ts`, `web/src/lib/server/relais-audio.ts`, `web/src/lib/server/retours.ts` ou classe équivalente, `web/src/routes/admin/+page.server.ts`, `web/src/routes/admin/+page.svelte`, les routes des résumés ajoutées par BL-071, `rssresume/newsletter.py` si les liens portent directement vers les pages du site ;
  - tests en face de chaque acceptation : écoute comptée une fois pour le bon profil/journée/jour d’écoute, retour compté une fois par profil/journée, retours isolés entre profils, seuls les admins voient les indicateurs, `tests/` unittest et `npm run check`/`npm test` verts.
- **Tests d'acceptation** :
  - [ ] une écoute et une consultation sont comptées pour le bon profil, une fois par journée consultée et par jour d’écoute ;
  - [ ] les retours « utile / pas utile » sont comptés une fois par profil et par journée ;
  - [ ] seules les personnes admin voient les écoutes et les retours dans `/admin` ;
  - [ ] `npm run check`, `npm test` et la suite unittest complète sont verts.
