# BL-102 - Rendre `RSSRESUME_PROFILES_DB` obligatoire pour la tournée
- **Catégorie** : pipeline
- **Priorité** : 2
- **Dépend de** : BL-056 (fusionné via PR #56)
- **Description** : depuis BL-056, le cache de scoring vit dans la base SQLite des profils :
  sans `RSSRESUME_PROFILES_DB` (mode dossier `RSSRESUME_PROFILES_DIR` ou document unique),
  `cache_scoring=None` et chaque passage renote tous les articles, sans persistance. Rendre
  la base obligatoire pour la tournée : `cli.py`/`profil.py` refusent de démarrer sans
  `RSSRESUME_PROFILES_DB` (message explicite, code de retour non nul), le mode dossier et les
  variables à profil unique disparaissent du chemin de la tournée (la migration dossier → base
  reste documentée : `python -m rssresume.api importer <dossier>`). L'API la rend déjà
  obligatoire. Conséquence à documenter dans README.md et FONCTIONNEMENT.md : une installation
  en mode dossier doit d'abord importer, et une journée est renotée une fois à la migration
  (~0,004 $ par profil). Le cache devient alors toujours présent : plus de cas `cache_scoring=None`
  dans `DigestService`.
- **Bénéfice attendu** : plus aucun mode où chaque tournée repaye le scoring de toutes les
  journées ; le cache SQLite est la seule voie.
- **Tests d'acceptation** :
  - [ ] sans `RSSRESUME_PROFILES_DB`, la commande de tournée échoue avec un message clair nommant la variable et la commande d'import ;
  - [ ] avec la base renseignée, la tournée démarre et le cache `scores` est lu/écrit ;
  - [ ] le mode dossier n'est plus proposé pour la tournée (doc à jour, plus de branche morte dans `cli.py`) ;
  - [ ] `DigestService` ne porte plus de cas `cache_scoring=None` ;
  - [ ] suite Python entière verte, `npm run check` et `npm test` verts (si le web est touché).
